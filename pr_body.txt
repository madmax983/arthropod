🚮 Smell: The `update_all_reactive_system` function in `crates/arthropod-ecs/src/systems/reactive.rs` had grown into a "God Function" (~140 lines) by manually polling and updating 8 different types of reactive components (Layout Width, ProgressBar, Flex Grow, Colors, Text, Computed Text, Transforms, Opacity) in one giant loop with deeply nested `if let` blocks. This made the function hard to read and modify.

✨ Solution: Extracted the logic for updating each individual property type into its own dedicated, static helper function (e.g., `update_color`, `update_text`, `update_layout_width`). Each helper takes `Option<&mut T>` for the specific reactive components it cares about, allowing the main system loop to simply call each helper sequentially. Used `.and_then` and `.map` to flatten the nested options where possible.

🧼 Benefit: Dramatically reduces the cognitive load of `update_all_reactive_system`, flattening the structure and isolating the update logic for each component type into easily testable and readable units.

🛡️ Verification: Tests passed. No logic changed.
