## 2026-06-29 - Widget Core Internal Module Encapsulation
**Tangle:** `widget-core/src/lib.rs` exposed 9 internal architecture modules (`form`, `layout`, `layout_bridge`, `primitive`, `context`, `input_state`, `layer`, `style`, `widget_trait`) as `pub mod`. This leaked the internal directory structure to all dependent crates, violating the strict `pub(crate)` encapsulation boundary rule and creating a "Sprawl" API surface.
**Blueprint:** Refactored the `pub mod` declarations to `pub(crate) mod` in `widget-core/src/lib.rs`. Maintained backward compatibility by explicitly re-exporting only the necessary cross-crate APIs via `pub use`, such as `layout_bridge::perform_layout` and `input_state::{ReactiveColorState, ...}`. Updated external usages in `arthropod`, `arthropod-ecs`, and `material-ui` to consume the clean, flattened API.

## 2026-06-29 - style-engine Internal Module Encapsulation
**Tangle:** `style-engine/src/lib.rs` exposed its internal architecture modules (`blend`, `corner`, `effect`, `paint`, `path`, `stroke`, `text`, `visual`) as `pub mod`. This leaked the internal directory structure to dependent crates (`arthropod`, `tui-renderer`), violating the strict `pub(crate)` encapsulation boundary rule and creating an unnecessary dependency on internal paths rather than the clean public facade.
**Blueprint:** Refactored the `pub mod` declarations to `pub(crate) mod` in `style-engine/src/lib.rs`. Re-exports via `pub use` already covered most required APIs, keeping the public facade intact. Updated external usages in `arthropod`, `tui-renderer`, and internal tests to consume the clean, flattened root API (e.g., using `style_engine::VectorPath` instead of `style_engine::path::VectorPath`).
